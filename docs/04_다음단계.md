## PPO 추격자 (구현 완료 2026-11-11, 실행은 `docs/05_실습장_실행가이드.md`)

| 항목 | 계획 |
|---|---|
| 라이브러리 | gymnasium 0.29.1 + stable-baselines3 2.3.2 (PPO), torch 2.3.1(Docker) |
| 래퍼 | `ooda/gym_env.py`: 추격자 시점의 gymnasium 환경. 도망자(와 기만체)는 내부에서 규칙 기반으로 움직이고, 유형은 에피소드마다 무작위(3종 혼합) |
| k 처리 | 래퍼 안에서 결정 시점에만 `step`을 받고, 사이 스텝은 행동 반복으로 내부 진행 → RL-B(각 k에서 학습)가 자연스럽게 구현됨 |
| 관측 | 20×20 다채널 격자(장애물, 출구 후보, 자기 위치, **현재 보이는 접촉**(`PursuerObs.contacts`, 진짜/기만체 구분 없음), **접촉 궤적**(시간 감쇠), **식별된 기만체 위치**(`decoy_id_pos`), 방문 흔적) + 스칼라(경과시간, 마지막 목격 후 경과) |
| 행동 | 5개 (정지, 상, 하, 좌, 우) |
| 보상 | 포획 +1, 도주 허용 −1, 스텝마다 −0.001, **잠재함수 기반 보상 성형**(접촉까지 거리, c=0.5, 최적 정책 불변, 결정 13) |
| 망 | CNN(conv 32→64→64 stride2 → 선형 256) + 스칼라 연결, 정책·가치 헤드 각 128 (`ooda/rl_policy.py`) |
| 공정성 | 추격자가 받는 정보는 FSM과 동일(시야 3, 출구 후보 위치, 지도 구조, 구분 없는 접촉, 식별 사건). 기만체의 과거 궤적을 환경이 따로 표시해 주지 않음(어느 접촉이 기만체였는지 연결은 RL이 추론). 기만 관련 보상 성형 없음 |
| 훈련 | PPO(n_steps 512/환경, batch 512, 4 epoch, lr 3e-4, γ 0.99, λ 0.95, ent 0.01). 6 k × 5 seed = 30개(k=1이 RL-A). 25만 스텝마다 검증 seed(20,000,000번대) 유형별 200판으로 최고 모델 저장. 실험당 1,000만 스텝(넉넉하게, 최고 모델은 검증으로 선택). 별도 파일럿 없이 본 학습 초반 k=1 실험으로 학습 여부 확인 |
| 스크립트 | `scripts/train.py`, `scripts/run_experiments.py`(일괄·GPU 배정·재개), `scripts/evaluate.py`(FSM과 RL을 같은 평가 seed로). `scripts/analyze.py`(회귀, k\*, 부트스트랩)는 평가 후 작성 |

**위험과 대비책**
- RL이 k=1에서 FSM을 크게 넘지 못할 수 있습니다 → 학습 예산, 관측, 망 구조를 먼저 노트북에서 점검합니다. 그래도 넘지 못하면 그 자체가 결과입니다("학습이 탐색-추격 휴리스틱을 넘지 못하는 조건").
- 노트북에는 torch CPU 버전을 따로 설치합니다: `pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cpu` (2.3.1은 Windows에서 DLL 오류)
- 노트북 CPU에서는 PPO 업데이트가 병목이라 초당 약 200스텝 → 본 학습은 반드시 실습장 GPU에서

## 사용자 확인이 필요한 것
1. **보정 방식의 역할 교환**: 공통 속도를 주 분석, 유형별 속도를 강건성 점검으로 (`02_설계결정_기록.md`의 결정 8)
2. 이동속도 비대칭(도망자 15/17)을 논문에서 어떻게 정당화할지 (Cops and Robbers 인용 + 침투조/기동타격대 해석)
3. **⚠️ 기만형 설계 문제 (미해결, 최우선)**: 기만형이 가장 잘 잡힙니다(k=1에서 58%, 돌진형 52%, 회피형 38%). 기만이 상대를 속이지 못하고 비용만 치르는 상태입니다.
   - 진단(2,000판/유형, k=1): FSM이 가짜 출구를 믿게 된 비율이 기만형 23%로, 돌진형(24%)과 차이가 없습니다. 즉 **속지 않습니다**. 게다가 가짜 출구를 믿은 판에서도 추격자가 82%를 잡습니다. 근접 시야(3칸)에서 바로 추격으로 넘어가므로 출구 추정이 승패에 거의 쓰이지 않기 때문입니다.
   - 개선안 v2(회피형 + 멀리서 보일 때만 가짜 출구 쪽으로)도 45%로, 회피형(38%)보다 약했습니다.
   - 근본 원인: 추격자가 **의도를 추론해서 그 판단에 따라 움직이는(commit) 구조**가 거의 없으면 기만은 공격할 대상이 없습니다. Boyd의 기만은 적의 Orient를 공격하는 것입니다.
   - 논의 중인 해법: 주기적인 원거리 감시 보고(ISR)로 추격자가 의도를 추론하고 대응을 결정하게 만들기 / 기만형을 '회피형 + 기만'의 중첩 구조로 재정의 / 기만형 제외. **사용자와 결정 후 재보정이 필요합니다.**

## 다음 구현: PPO 추격자 (계획)

| 항목 | 계획 |
|---|---|
| 라이브러리 | gymnasium 0.29.1 + stable-baselines3 2.3.2 (PPO) |
| 래퍼 | `ooda/gym_env.py`: 추격자 시점의 gymnasium 환경. 도망자는 내부에서 규칙 기반으로 움직이고, 유형은 에피소드마다 무작위(3종 혼합) |
| k 처리 | 래퍼 안에서 결정 시점에만 `step`을 받고, 사이 스텝은 행동 반복으로 내부 진행 → RL-B(각 k에서 학습)가 자연스럽게 구현됨 |
| 관측 | 20×20 다채널 격자(장애물, 출구 후보, 자기 위치, 현재 보이는 도망자, 마지막 목격 위치(시간 감쇠), 방문 흔적) + 스칼라(경과시간, 마지막 목격 후 경과) |
| 행동 | 5개 (정지, 상, 하, 좌, 우) |
| 보상 | 포획 +1, 도주 허용 −1, 스텝마다 −0.001 (탐색 촉진용 보상 성형은 최소화) |
| 망 | 작은 CNN 또는 MLP. 노트북에서 소규모로 비교한 뒤 결정 |
| 공정성 | 추격자가 받는 정보는 FSM과 동일(시야 3, 출구 후보 위치, 지도 구조) |
| 훈련 | 노트북: 짧은 학습으로 동작 확인 → 실습장(Docker, 16 CPU, RTX 2080×2): 본 학습. RL-A 5시드 + RL-B 6k×5시드 |
| 스크립트 | `scripts/train.py`(설정은 인자로), `scripts/evaluate.py`(FSM과 RL을 같은 평가 seed로), `scripts/analyze.py`(회귀, k\*, 그림) |

**위험과 대비책**
- RL이 k=1에서 FSM을 크게 넘지 못할 수 있습니다 → 학습 예산, 관측, 망 구조를 먼저 노트북에서 점검합니다. 그래도 넘지 못하면 그 자체가 결과입니다("학습이 탐색-추격 휴리스틱을 넘지 못하는 조건").
- 노트북에는 torch CPU 버전을 따로 설치해야 합니다: `pip install torch --index-url https://download.pytorch.org/whl/cpu`
